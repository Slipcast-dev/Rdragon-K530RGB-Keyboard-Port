# Восстановленный протокол обмена (статический анализ, 27 октября 2026)

Источник: дизассемблирование `Redragon K530RGB Keyboard.exe` (хеш в `manifest.json`). **На реальной клавиатуре не проверено.** Прочитанные значения — по логике кода, а не по захвату трафика.

## Как получен код

Установщик содержит три вложенных файла InstallShield: `data1.cab` (521824 байт, смещение 741417), `data1.hdr` (23239, смещение 1263281) и `data2.cab` (10648766, смещение 1286563). Файлы приложения лежат в группе `DefaultComponent` и распаковываются `unshield` (коммит feaa32f); хеши совпали с manifest.json.

## Транспорт

- Таблица функций HidServ.dll в exe (VA 0x6E4FC8…): +4 hModule, затем по порядку GetProcAddress: Debug, Init, End, RequestGetDeviceCount, DeleteRequestFromUnitId, DeleteRequestFromHandle, RequestWrite, RequestWriteOne, RequestStatusWrite, RequestStatusGet, RequestAsyncRead, RequestStatusSetFeature.
- Отправка пакета — функция VA `0x43FD90(buf, len, resp, resp_len, &status)`: копирует команду в 64-байтовый буфер (остаток нулями), отправляет через `RequestWriteOne`, ждёт ответ до 1000 мс, повторяет до 3 раз (при таймауте и при несовпадении байта 3 ответа с байтом 3 запроса; байт 7 ответа `0xFF`/`0xFE` — ошибка/занято).
- Буфер 64 байта, байт 0 = `0x04` = Report ID 4 vendor-коллекции `FF1C:0092` (на реальном устройстве — интерфейс 1, 63 байта данных). Это согласуется с дескриптором в `research/device/k530-usb-descriptors.md`.

## Формат пакета (64 байта)

| Байт | Значение |
|---|---|
| 0 | `0x04` (Report ID) |
| 1–2 | Контрольная сумма: сумма байтов 3…63 (16 бит), младший, затем старший |
| 3 | Команда |
| 4 | Длина данных |
| 5–6 | Адрес (младший, старший) |
| 7 | Статус (в запросе 0; в ответе `0xFF` или `0xFE` — ошибка) |
| 8… | Данные, до 56 байт |

## Команды (по коду)

| Cmd | Функция VA | Назначение |
|---|---|---|
| `0x01` | `0x440020` | Начало сеанса (без данных) |
| `0x02` | `0x4400D0` | Конец сеанса; перед отправкой задержка 10 мс |
| `0x06` | `0x440FE0(data, len, addr)` | Запись `len` байт по адресу `addr` |
| `0x05` | `0x4410B0(out, len, addr)` | **Чтение** `len` байт с адреса `addr`; данные в ответе с байта 8 (до 56 байт) |
| `0x17` | `0x440F00(data, len, idx)` | Запись блока; адрес = `профиль*512 + idx*3` (профиль — глобальная по VA `0x6E0FA4`), в коде вызывается с len=54 для 8 блоков |

Типичная последовательность записи: `01` → одна или несколько `06`/`17` → `02`. Пример (VA `0x418D21`): begin, запись 1 байта `0x00` по адресу `профиль*42+15`, end.

## Схема профиля и подсветка (анализ обработчиков UI)

Профиль — блок по адресу `профиль*42`, где `профиль` — глобальная переменная (VA `0x6E0FA4`). Запись по командам `01 → 06 → 02`. Поля, найденные в обработчиках кнопок подсветки (VA `0x41A930…0x41AD9E`, `0x41D040…0x41D439`, `0x41F2A0…0x41FECC`):

| Смещение в профиле | Размер | Значение (по коду) | Уверенность |
|---|---|---|---|
| +0 | 1 | **Номер режима подсветки**: 1–18 и 20 (19 нет; ветка `switch` по таблице переходов VA `0x41D054`, 20 ячеек) | высокая |
| +4 | 1 | Флаг «цвет»: 0 — задан один цвет из +5…+7; 1 — режим «Colourful» (кнопка DC в `Lang0409.ini`). В обработчике режима пишется `глобальный флаг != 0` | средняя |
| +5…+7 | 3 | Цвет R, G, B (порядок из `COLORREF`: R — младший байт) | высокая |
| +1 | 1 | Значения 21–25 (пять уровней, обработчик VA `0x418775`) — вероятно, уровень яркости или скорости | низкая |
| +3 | 1 | 0 или 255 (VA `0x41F168`/`0x41F269`) — назначение не выяснено | низкая |
| +18 | 1 | 0 (VA `0x41FC8D…0x41FECC`) — назначение не выяснено | низкая |

Соответствие номера режима и названия (`Lang0409.ini`, раздел `[MODE]`, названия — машинный перевод с китайского): 1 Go with the stream, 2 Clouds fly, 3 Winding paths, 4 The trial of light, 5 Breathing, 6 Normally on, 7 Pass without trace, 8 Ripple graff, 9 Fast run without trace, 10 Snow winter jasmine, 11 Flowers blooming, 12 Swift action, 13 Hurricane, 14 Accumulate, 15 Digital Times, 16 Both ways, 17 Surmount, 18 Fast and the Furious, 20 Coastal.

Смена режима в программе = `01` → `06(data=[режим], len=1, addr=профиль*42+0)` → `06(data=[флаг], len=1, addr=профиль*42+4)` → `02`. Пример: режим 1, VA `0x41D062…0x41D0B2`.

Пример цвета (VA `0x41A930`): три байта `EB 63 1E` пишутся по `профиль*42+5`, флаг +4 = 0.

## Чтение профилей (загрузчик в штатной программе, VA `0x42398C…0x4239CF`)

После проверки устройства (VA `0x440190`) программа выполняет: `01 begin` → три чтения `05` по **56 байт** с адресов **0, 42, 84** (из каждого сохраняет первые 42 байта) → `02 end`. Это три профиля по 42 байта. Из загруженных байт программа берёт: +0 режим, +1/+2/+3 числовые параметры, +4 флаг (≠0 → «Colourful»), +5…+7 цвет (+5 — R), +15 (ограничивается 3), +18, +19, +24…+27 (второй цвет). Эта раскладка совпадает с адресами записи из обработчиков UI и подтверждает схему профиля выше.

Проверка ответа (VA `0x43FD90`): байт 3 ответа равен команде запроса; байт 7 равен `0xFF` или `0xFE` — ошибка. Тайм-аут ответа 1000 мс, до трёх попыток.

## Опасная функция, не использовать

VA `0x441190` формирует пакет с байтами `4, ?, ?, 0xEE, 0xEE` и отправляет его без ответа (`0x43FF70`); вызывается один раз из кода проверки устройства (VA `0x43FCD3`). Назначение не выяснено (возможно, сброс или переход в служебный режим). В k530diag этой команды нет и добавлять её без отдельного разбора нельзя.

## Что не найдено

- Назначение полей +1, +3, +18 (яркость, скорость, направление), номер текущего профиля `0x6E0FA4` на самом устройстве.
- Какие адреса безопасно писать: запись в неверное место может испортить профиль или макросы клавиатуры.

## Следующий шаг

Запустить `k530diag read-profile` (сначала без `--send`, чтобы увидеть пакеты), затем с `--send`, сверить прочитанные профили со схемой. Первое чтение на реальной клавиатуре ещё не выполнялось. Первый эксперимент — только чтение (после поиска команды чтения), затем запись одного параметра с резервной копией прочитанного блока.

## Первое чтение на реальной клавиатуре (27 октября 2026)

`k530diag read-profile --send` выполнен; результат — `research/device/profiles-read-1.txt`. Устройство ответило на `begin`, три `read` и `end` без ошибок: **формат пакетов, контрольная сумма и адреса 0/42/84 подтверждены**. Записи не выполнялись.

Все три профиля одинаковы: `14 04 02 00 ff ff 00 00 09 00 …` (профиль 1 отличается только байтом +21 = `02`).

| Смещение | Значение | Вывод |
|---|---|---|
| +0 | 20 (0x14) | режим 20 «Coastal» — входит в известный набор 1–18, 20 |
| +1 | 4 | **не** 21–25, как предполагалось: гипотеза про +1 неверна |
| +2 | 2 | неизвестно |
| +3 | 0 | неизвестно |
| +4 | 255 | не 0/1: флаг «Colourful» проверяется как «≠ 0» |
| +5…+7 | `ff 00 00` | красный; при включённом +4 цвет, по-видимому, не используется |

Нужна сверка с физическим состоянием: какой режим, яркость и скорость сейчас показывает клавиатура (проверить без записи).

## Первая запись (27 октября 2026): команда 0x06 и режим +0

`k530diag test-mode 6 --hold 10 --send`: записан байт +0 = 6 во все три профиля, чтение подтвердило `[6, 6, 6]`, через 10 с возвращено `[20, 20, 20]`, полный блок после возврата совпал с резервной копией (`research/device/profiles-backup-*.txt`). **Принятие записи и откат подтверждены чтением.** Изменилась ли видимая подсветка, из терминала проверить нельзя — нужна визуальная проверка человеком.

## Яркость и цвет, проверено на клавиатуре (27 октября 2026)

Меню-приложение `tools/k530menu`, проверка человеком у клавиатуры:

- **Режим** (+0): работает, подтверждено.
- **Яркость** (+1, значения 0–4): работает, подтверждено (максимум = 4).
- **Цвет** (+4 = 0, +5…+7 = R, G, B): записывается и читается назад верно; **в режиме 6 «Normally on» цвет меняется**, в режиме 20 «Coastal» не меняется (режим использует собственную палитру). Для остальных режимов не проверено.
- Штатная программа для готового цвета пишет `+4 = 0` и `+5…+7`, для выбора произвольного цвета — только `+5…+7`, для «Colourful» — `+4 = 1` (VA `0x41F390`, `0x41F4F0`, `0x41F440`).
- Поля +2 (вероятно, скорость; у штатной программы слайдер инвертирован для значений 0–4), +3 и остальные пока не используются и не проверены.

Ограничение сборки: подпись приложения ad-hoc, доступ «Мониторинг ввода» привязан к сборке и слетает после пересборки.
